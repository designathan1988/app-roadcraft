# Internationalisation

**Files:** `src/ui/i18n/` · **Tests:** `tests/ui/i18n.spec.ts`

## The rule

**The code is English. Only the interface is translated.**

Keys, identifiers, file names, folder names, comments, documentation and commit
messages are English whatever language the player has selected. The dictionaries
in `src/ui/i18n/` are the only place another language appears.

The model follows the same rule: a road class stores a `nameKey`, a structure
stores a `key`. The model states what the text is *about*; `src/ui/labels.ts`
renders it. That is what lets the language change without touching the document,
the network, the simulation or any saved map.

## How it works

| | |
|---|---|
| `index.html` | elements carry `data-i18n` (text), `data-i18n-title`, `data-i18n-label` (aria-label) or `data-i18n-html` |
| `applyTranslations(root)` | rewrites every element that declares a key |
| `t(key, params)` | looks a key up, substituting `{name}` placeholders |
| `plural(key, count)` | picks `key.one` or `key.other`, passing `{count}` |
| `setLanguage(code)` | stores the choice, re-applies the markup, notifies listeners |
| `onLanguageChange(fn)` | for anything rendered from script rather than markup |

`initLanguage()` runs before anything reads a label, so no frame is ever painted
in the wrong language. It prefers a stored choice, then the browser's own
languages, then English.

A missing key falls back to English and then to the key itself — so a gap shows
up as a readable string rather than as a blank element.

## Adding a string

1. Add the key to `src/ui/i18n/en.ts` **and** `src/ui/i18n/pt-BR.ts`.
2. In markup, use `data-i18n="your.key"`; in code, `t('your.key')`.

Never write a player-facing string inline. A test fails if the two dictionaries
drift apart, if placeholders differ between them, if a string is empty, or if the
markup names a key no dictionary defines.

## Adding a language

1. Copy `pt-BR.ts`, translate the values, keep every key and every placeholder.
2. Import it in `src/ui/i18n/index.ts`, add it to `DICTIONARIES` and to
   `LANGUAGES`, and extend `LanguageCode`.
3. Add its prefix to the detection in `detect()` if you want it picked up
   automatically.

Nothing else changes. The selector in the top bar is built from `LANGUAGES`.

## Things rendered from script

`applyTranslations` only reaches elements that carry a key. Anything built in
TypeScript — the road-class buttons, the hint bar, the status bar, the inspector
— re-renders itself from the `onLanguageChange` listener in `main.ts`. If you add
another such surface, add it there.
